TLDR

The router is the entry point. It fingerprints the project to pick one engine (a project.godot means Godot), keeps an existing project's pinned version, then sorts the request into three additive groups and reads only the chosen skills, saying what it loaded. Fifteen discipline skills each own one portable concept, such as save-systems, input-systems, camera-systems, game-feel or performance-optimization, and leave the engine's API to its engine skill. Nine genre playbooks, from platformer to visual-novel, set out a game's core loop, must-have systems and tuning knobs, and name the disciplines to build each part from instead of re-teaching them. Two workflows cover process: prototype-fast tests whether a mechanic is fun, and game-jam scopes a jam entry to the clock and plans it through to submission. Asking for a double jump in a Godot game, say, loads the Godot movement skill and platformer, nothing else. For a new project with no engine preference the router picks Godot; a custom engine is kept, and the concepts are mapped onto its own APIs. The engine skills it routes to, and steam-publish and itch-publish, aren't listed on SkillHub, but both installs bring them. Every skill here but the router also works alone.

Its skills, in the order they're used

The ones marked “Only in the bundle” need the rest of it, so they're only listed here. The others also have their own entry in the skills list.

  1. router

    Only in the bundle 9.8K total downloads

    Detects your game's engine from its project files and your task from the request, then loads only the matching skills from this game-dev collection.

    Picks and reads the bundle's other skills, plus the repo's engine skills, steam-publish and itch-publish, which SkillHub doesn't list; alone, it has nothing to load.
