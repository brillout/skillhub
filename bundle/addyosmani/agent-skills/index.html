Use it when
you want your agent to follow a senior engineer's process at every phase, from a vague idea to a production launch
It does
gives each phase its own skills: interview, spec, plan, build in tested slices, debug, review, simplify, secure, commit, document and ship

a spec you approve, a plan in tasks/plan.md and tasks/todo.md, small tested commits, a five-axis code review and a launch checklist with a rollback plan

Commands

Install whole

TLDR

Addy Osmani's pack maps software work onto six phases. using-agent-skills, the entry point, picks the skill for a task and sets shared rules: state assumptions, push back, stay in scope, verify before claiming done. Define: interview-me finds out what you actually want, idea-refine turns a rough idea into a one-pager, spec-driven-development writes the spec and waits for your approval, and constraint-driven-development records the quality bar in CONSTRAINTS.md. Plan: planning-and-task-breakdown turns the spec into ordered tasks. Build: context-engineering loads the right context and source-driven-development checks framework code against official docs; incremental-implementation and test-driven-development then deliver each task as small tested commits, helped by frontend-ui-engineering and api-and-interface-design, with observability-and-instrumentation adding telemetry alongside and doubt-driven-development sending non-trivial decisions to an adversarial reviewer. Verify: browser-testing-with-devtools and debugging-and-error-recovery. Review: code-review-and-quality, code-simplification, security-and-hardening and performance-optimization. Ship: git-workflow-and-versioning, ci-cd-and-automation, documentation-and-adrs, deprecation-and-migration and shipping-and-launch. Every skill but the router has a table of excuses to reject and a verification checklist, and works alone. The repo also ships reviewer personas and shared checklists that only a whole-repo install brings.
