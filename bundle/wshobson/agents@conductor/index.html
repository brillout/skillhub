Conductor Bundle · 3 skills

Use it when
you want an agent to build features from written project context and an agreed plan, across many sessions, approving each phase before it moves on
It does
keeps project context files, turns each feature, bug, chore or refactor into a track, a unit of work with a spec and phased plan, then builds it test-first
You get
a conductor/ folder of product, tech-stack and workflow files and a tracks.md registry; per track, a spec.md, a plan.md marked with task status and commit SHAs, and metadata
Pauses

Commands

Based on

TLDR

Three skills behind Conductor, a wshobson/agents plugin, one per stage of its cycle: context, then spec and plan, then implementation. context-driven-development keeps a conductor/ folder of Markdown files the agent reads before each piece of work: product.md for what's built and why, product-guidelines.md for voice and terminology, tech-stack.md, workflow.md for rules such as TDD, commit conventions and coverage targets, and tracks.md, the registry of tracks. It gives starter templates, when to update each file and a checklist to run before starting a track. track-management turns a feature, bug, chore or refactor into a track: a folder with spec.md (requirements, testable acceptance criteria, scope, dependencies, risks), plan.md (phases of tasks, each ending in verification) and metadata.json. workflow-patterns then works through the plan one task at a time: mark it in progress, write failing tests, make them pass, refactor, reach 80% coverage, commit, attach a git note and record the SHA in plan.md. At the end of each phase it runs the full test suite, lists manual checks and waits for your approval before a checkpoint commit. Setting up, creating tracks and reverting call /conductor commands, which come with the plugin, not with the skills.

codex plugin marketplace add wshobson/agents && codex plugin add conductor@claude-code-workflows
