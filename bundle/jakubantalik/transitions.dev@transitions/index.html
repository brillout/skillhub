TLDR

transitions.dev is a collection of portable CSS transitions, and these two skills split the work on it. transitions-dev holds the catalog: more than thirty transitions, such as dropdowns, modals, toasts, tabs, skeleton loaders and AI thinking states, decision rules that match a UI pattern to one of them, and a five-step install that pastes the snippet verbatim with its reduced-motion guard. transitions-polish is its add-on for motion that already exists: it scans styles, CSS-in-JS and Tailwind values for hardcoded durations, easings, distances, scales and blurs, maps each to the token whose documented usage matches, and checks the rules between values, such as closes faster than opens and short total staggers, before applying the changes you confirm. transitions-dev's snippets ship literal values, which transitions-polish can map back onto the tokens; each skill also works alone, and transitions-polish restates the values it needs. transitions-dev's own transitions refine command also maps values to tokens, without the polish rules. Both skills define a transitions review command: in transitions-dev it finds where a whole transition would fit, in transitions-polish it audits existing values.
