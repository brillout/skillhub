TLDR

Five skills from Warp's shared repo that take a substantial feature from intent to checked code. spec-driven-implementation is the entry point: it decides whether the feature needs specs at all (small bug fixes, simple refactors and narrow UI tweaks usually don't), makes sure a Linear issue exists to name the specs folder after, and hands its three main steps to the next three skills. write-product-spec writes PRODUCT.md: the feature's behavior from its user's side, as numbered, testable rules with no implementation details, after asking for a Figma mock when there's UI. write-tech-spec reads that spec and the code, then writes TECH.md: the current system, the proposed changes and trade-offs, and a test or check for each important rule. implement-specs builds from the approved specs, updating them as soon as the implementation changes, in the same PR when practical, so they describe what ships. validate-changes-match-specs, which you run yourself near the end or in review, lists each material mismatch between the branch's specs and its code, checks what security specs allow and prevent, and asks whether to fix the code or the spec. They're written for Warp's own features; all but the entry point and implement-specs also work alone.

Its skills, in the order they're used

The ones marked “Only in the bundle” need the rest of it, so they're only listed here. The others also have their own entry in the skills list.

  1. spec-driven-implementation

    Only in the bundle 28.9K total downloads

    Runs a spec-first workflow for large features: product spec, tech spec when needed, then code, with specs kept current in the same PR.

    Loads write-product-spec, write-tech-spec and implement-specs for its three main steps; on its own it only decides whether specs are needed and files the Linear issue.

  2. write-product-spec

    28.9K total downloads

    Writes a PRODUCT.md spec describing a feature's behavior from its user's side as numbered, testable rules, before implementation starts.

  3. write-tech-spec

    28.8K total downloads

    Researches the codebase and writes a TECH.md implementation plan for a feature, with commit-pinned code links and tests mapped to the product spec.

  4. implement-specs

    Only in the bundle 28.6K total downloads

    Builds a feature from its approved PRODUCT.md and TECH.md, updating both specs in the same PR whenever the implementation changes course.

    Starts only once PRODUCT.md, and TECH.md when warranted, exist and are approved: the specs that write-product-spec and write-tech-spec write.

  5. validate-changes-match-specs

    25.3K total downloads

    Checks a branch's code against the product, tech and security specs it introduces, then resolves each mismatch the way you choose.
