TLDR

Ponytail casts the agent as a lazy senior developer: the best code is the code never written. Its core skill, ponytail, stays on for the session. Before writing, the agent reads the code the task touches and lists every place the change must reach; then it takes the first option that fully works, from skipping what wasn't asked for to reusing the codebase, the standard library or an installed dependency, and only then writes the minimum, with one small test for non-trivial logic. Each known shortcut gets a comment: shortcut: <the limit>, <when to upgrade>. The other skills run once and change no code. ponytail-review checks one change, reading its callers, tests and README, and ponytail-audit maps a whole repo and traces its data flows. Both rank findings as correct, safe, holds under load, tested, fast and lean, need a concrete failing case for each, number them so you can say "fix 2 and 5", and count a shortcut: comment that names its limit as a decision. ponytail-debt gathers those comments into one ledger and tags the ones with no upgrade trigger, and ponytail-help prints the levels, commands and settings.
