Epic breakdown workflow Bundle · 6 skills

Use it when
you want a product idea taken through requirements, architecture and planning documents before anyone writes code
It does
runs six prompts in order, each written for a role: epic PRD, epic architecture, feature PRD, implementation plan, GitHub project plan, test plan
You get
Markdown files under /docs/ways-of-work/plan/{epic-name}/: epic.md and arch.md, then a folder per feature for its PRD, plans and test documents
Gaps
the last two steps look for the feature PRD at {feature-name}.md rather than the prd.md the PRD step writes, and for a technical-breakdown.md no step writes
Assumes
TypeScript, Next.js, Turborepo, tRPC, Stack Auth, shadcn/ui and Docker, in the architecture and implementation steps
Output
documents only: GitHub issues are drafted in the project and test plans, not filed

TLDR

Six prompts that hand documents down a chain, each played by a role from product manager to QA engineer, all saved under /docs/ways-of-work/plan/{epic-name}/. breakdown-epic-pm turns an epic idea into epic.md: problem, personas, user journeys, requirements, KPIs, what's out of scope and business value, asking questions when the idea is thin. breakdown-epic-arch writes arch.md beside it: a layered Mermaid system diagram, the features and technical enablers, the stack, technical value and a T-shirt size. breakdown-feature-prd takes one feature or enabler of the epic and writes its PRD, with user stories and acceptance criteria, in the feature's own folder. breakdown-feature-implementation turns that PRD into implementation-plan.md: architecture and entity-relationship diagrams, API design and a frontend component tree. breakdown-plan then drafts the GitHub work, an Epic > Feature > Story/Enabler > Task hierarchy with issue templates, priorities, estimates and dependencies, in project-plan.md and issues-checklist.md, and breakdown-test adds a test strategy, test issue checklist and QA plan built on ISTQB test techniques and the ISO 25010 quality model. Those last two expect files the earlier steps don't write at those paths, so point them at yours. The first four also work alone, from an idea or a PRD you supply.
