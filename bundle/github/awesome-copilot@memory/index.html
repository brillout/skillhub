TLDR

Two commands that share one file layout. /remember takes a lesson, such as a mistake the agent keeps repeating, and writes it as a short, generalized rule into <domain>-memory.instructions.md for a domain like clojure or git-workflow, creating the file if needed. It picks the domain unless you name one, asks you when unsure, and reads the existing memory and instruction files first so it doesn't repeat them; a lesson that fits no domain goes into memory.instructions.md. applyTo patterns in each file's front matter say which files its rules apply to. Lessons accumulate there. When a domain's memories have matured, /memory-merger >domain lists each one with where it would go in <domain>.instructions.md and waits for your go, drafts the merge until no detail is lost and nothing is repeated, then writes the instruction file, combining both files' applyTo patterns, and removes the merged lessons from the memory file. It takes one domain per run. Both work in the global scope by default, or in the workspace.
