TLDR

BMad's build workflow takes a change from intent to a local commit. It starts from what you hand it: a ticket from BMad's ticket tree of initiative, epic and story files, a plan file to resume, or a plain description; given nothing, it picks the next ready ticket. It checks that the working tree is clean and the branch fits, and offers to split off extra independently shippable goals into deferred-work.md. It investigates the code, then writes a plan file. A change of about 100 lines or fewer gets a short plan and is built in the session. A larger one gets the intent, a code map of what to touch, reuse and leave alone, tasks, Given/When/Then acceptance criteria and verification commands; once you approve, a fresh subagent implements it from the plan alone. Then a reviewer subagent reads the diff; a thorough review runs four lenses instead. The agent checks each finding against the code, fixes simple ones this change caused, defers older problems and logs every verdict in the plan; on the larger route, a finding traced to the plan or the intent reverts the code and re-plans. It then commits and offers a pull request or bmad-walkthrough.
