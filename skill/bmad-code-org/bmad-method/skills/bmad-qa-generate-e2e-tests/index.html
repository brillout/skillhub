TLDR

BMad's QA skill adds tests for behavior that already works, so later changes can be checked against it. It finds the feature from your request, a ticket in review in BMad's ticket tree or the current branch, or asks, offering to list the features with no end-to-end coverage by how much a regression would hurt. It writes each scenario as one sentence a product person would recognize, marks those already covered, and waits for your confirmation. It then reads how the project already tests: the runner, where tests live, how the app starts, test data, authentication and the CI job, and runs the existing suite once; with no harness at all, it proposes one and asks before adding any dependency. Each test goes through the UI by role, label or text, or through the public API, asserts the visible outcome, waits on conditions rather than time, creates its own data and fails for one reason. Product code changes only where the harness needs it, such as a test id, and each change is listed in the report.
