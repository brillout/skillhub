TLDR

BMad's retrospective reads the record an epic left behind rather than anyone's memory of it. It resolves the epic from a folder, id or slug, or offers the finished ones, and warns when tickets are still unfinished, which forces a rejected verdict unless you override it. It then lists what exists and what is missing, using a bundled script to derive each plan's diff range and commits. The analysis looks for problems that only show across the whole epic: changes to the dependency structure, the same problem solved twice, files that grew too large session by session, diverging patterns and gaps between spec and code. It hands the diff to bmad-review for adversarial, edge-case and verification-gap lenses, and exercises changed behavior end to end. A finding without a file, line, commit or log reference is dropped. On request, bmad-party-mode lets BMad's personas discuss the findings. It proposes a decision record (ADR) for each hard-to-reverse choice in the plans and writes only those you approve. The verdict judges the epic against its own requirements and done-when criteria. It also checks whether the previous retro's action items landed, and resumes from its document if interrupted.
