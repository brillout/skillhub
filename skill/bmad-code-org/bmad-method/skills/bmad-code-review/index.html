TLDR

BMad's code review finds what to review from your request, a ticket in review in BMad's ticket tree, or the current branch, writes the diff to a temp file, and collects the commit messages as the change's own claims. A thorough review launches its reviewers at once, each without the others' findings: a blind hunter that sees only the diff, an edge-case hunter, a verification-gap reviewer that looks for behavior no test checks, and, when an intent is available, an intent-alignment auditor that compares the diff with it. The agent then checks every finding at its file and line, grades the real ones high, medium or low, rejects false ones with the evidence, and merges findings with the same root cause. Each survivor becomes a decision for you, a patch, or a deferral for problems this change didn't cause, which also go to deferred-work.md. With a plan file, the findings are written into it. A non-interactive run, such as from CI or another workflow, applies the patches without asking.
