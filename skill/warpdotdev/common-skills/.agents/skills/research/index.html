research

Use it when
an answer means reading many files, long logs or a big diff: how X works, where Y is used, why Z fails
It does
briefs one local, read-only subagent, or several in parallel for independent sub-questions, on the exact question, where to look and what to return
You get
a direct answer, the key file paths and symbols as evidence, and any caveats, without the noise in the main context
Skip it when
you'd read two or three known files, run one grep, or need the raw files to edit next
Models
names gpt-6-luna-medium for simple searches and gpt-6-luna-xhigh for involved ones

TLDR

Context is the main agent's scarcest resource, and reading twenty files to find the three that matter fills it with noise. This skill hands the digging to a subagent and keeps only the conclusion. The test is whether the noise avoided outweighs a subagent's latency and tokens: good fits are a failing test's root cause, how a class is used across a repo, or a summary of a 4,000-line PR. Subagents always run locally, even under a cloud agent, and use a search model rather than the parent's. One is the default; several run in parallel only when the question splits into independent parts. The brief states the question, where to look, that the work is read-only, and that it should return a distilled answer with file:line evidence rather than a transcript. A bloated report gets a follow-up to the same subagent. Afterwards the agent works from the result and reads files itself only when it needs to edit them.
