diagnose-ci-failures

Use it when
a pull request's CI is red and you want to know why before anyone touches the code
It does
finds the branch's PR with gh, sorts its checks into passed, failed and running, pulls the failed logs and groups the errors
You get
a plan: the failing checks, the errors and where they are, the fix for each group, and the commands to verify it
Needs
the GitHub CLI, gh, and a create_plan tool for the plan document
Tuned for
Rust projects: its error groups and check names assume cargo fmt, Clippy, WASM builds and macOS, Linux and Windows test runs

TLDR

A fixed sequence for red CI. The agent finds the PR for the current branch with gh, offering to open one with create-pr if there's none, and reads the status of every check. If some are still running, it reports what has passed and failed so far and suggests waiting. For each failed check it pulls the failed logs and extracts error messages with their files and lines, lint names, failing tests and stack traces, then groups them: formatting, linting, compilation, tests, and platform-specific failures such as WASM or one operating system. The plan, made with a create_plan tool, states the problem, what failed where, the fix for each group and the commands to verify it, and points to the fix-errors skill for how to fix each kind of error. It never edits code itself. It sets GH_PAGER=cat on every gh call, and treats tests that fail locally but passed in CI as likely flaky or specific to the environment.
