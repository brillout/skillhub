Only works inside its bundle: Starts only once PRODUCT.md, and TECH.md when warranted, exist and are approved: the specs that write-product-spec and write-tech-spec write. Install Warp spec workflow instead.

TLDR

The building step of the spec workflow. It first confirms that PRODUCT.md exists, TECH.md too when the feature called for one, and that both have been reviewed and approved enough to start. PRODUCT.md is the source of truth for what users see, TECH.md for architecture, sequencing and the shape of the implementation. The agent breaks the work into concrete steps, builds against the specs, and adds tests and verification as the work lands. For large or long-running features it may offer a PROJECT_LOG.md of checkpoints and explored paths, or a DECISIONS.md of product and technical decisions, only when they'd help. When building shows that behavior or design should change, it updates the specs right away rather than at the end, in the same PR as the code, so the PR describes the feature that actually ships. Before calling it done, it checks the code against the current specs with unit, regression, and integration or end-to-end tests that follow the repo's conventions.
