check-impl-against-spec

Use it when
an automated review with review-pr finds spec_context.md, the PR's spec context: product behavior, tech details or both
It does
lists the spec's commitments, compares them with the diff and checked-out code, and flags only material drift: missing behavior, contradictions, significant unplanned scope, skipped validation or migration steps
You get
spec findings folded into review.json: broad drift in the summary, inline comments only on changed lines, each at least an important concern
Doesn't
write its own report, post to GitHub, or flag harmless differences in naming, structure or technique

TLDR

A supplement to review-pr, not a separate review. It runs only when spec_context.md exists, alongside pr_diff.txt and, when present, the PR description. From the spec it extracts the required behaviors, the files or subsystems it said to change, its constraints, and any required validation, migration or follow-up steps, then checks the diff and the checked-out branch for each. Small implementation choices that keep the spec's intent are accepted: it doesn't demand a one-to-one match or speculate about details the spec doesn't state. Material drift goes into the same review.json that review-pr writes, in the summary or as inline comments tied to changed lines, and nothing is added just to say the code matches.
