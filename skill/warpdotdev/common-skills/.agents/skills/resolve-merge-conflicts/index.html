resolve-merge-conflicts

Use it when
a merge, rebase, cherry-pick or stash pop stops on conflicts
It does
runs a bundled Python script that lists the unresolved files, then shows one file's conflict hunks with ours, base and theirs and a compact diff
You get
the conflicts resolved and staged, with no markers left and targeted tests, builds or linters run on the touched area
Keeps
context small: whole files are opened only when the compact view isn't enough
Needs
Python 3; its commands call the script at .agents/skills/resolve-merge-conflicts/scripts/ in your repo

TLDR

The point is to keep the agent's context small. A bundled Python script first summarizes the conflict: which files are unmerged, which index stages exist and how many hunks each file has. The agent then takes one file at a time, asking the script for just that file: nearby lines, the ours, base and theirs versions of each hunk, and a compact diff between ours and theirs. It takes one side whole with git checkout --ours or --theirs, or edits the file and removes the markers, reading more of the file only when the compact view isn't enough to decide. Conflicts that leave no markers in the file, such as add/add or modify/delete, are shown from the index stages. Options print every conflicted file at once, output JSON, or change how many context lines and how much output it shows. It's done when no unmerged paths and no conflict markers remain, targeted tests, builds or linters have run for the touched area, and the resolved files are staged.
