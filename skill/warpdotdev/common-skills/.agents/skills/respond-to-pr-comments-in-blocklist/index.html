respond-to-pr-comments-in-blocklist

Use it when
you want to answer a PR's review comments and post the replies back to GitHub, not just read them or fix code
It does
skips bot overviews and threads you already answered, then asks per comment: apply the recommended fix, explain it, acknowledge without changes, or something else
You get
the fixes made and checked, an optional commit and push, then replies posted with gh and approved threads resolved
Modes
one by one, fixing as you go, or collect every decision first and apply the fixes in a batch
Needs
the GitHub CLI, gh, and an ask_user_question tool for its multiple-choice prompts, as in Warp's agent

Replies it posts start with [Warp Agent], and commits it makes carry a Warp Agent co-author line.

TLDR

Written for Warp's agent, which supplies the ask_user_question and insert_code_review_comments tools it calls. It starts from comments already shown in the conversation, typically by the /pr-comments skill, or fetches and displays them first with gh. Automated status comments from Warp, Oz or code-review bots, resolved threads and threads whose latest reply is yours are skipped; when unsure, a comment stays in. For each one the agent restates the author, location and gist with a path:line reference, inspects the code when the fix isn't obvious, and asks what to do, always with an Other option for your own approach; choosing explain gets you context and the question again. It keeps a decision record with a draft reply per comment, changes only what the comments ask, preserves unrelated work, runs the narrowest useful checks and reviews the diff. It asks before committing and pushing, so reviewers see the code before the replies. Nothing reaches GitHub until you approve a preview grouped by comment; replies go through the REST API and threads are resolved through GraphQL.
