review-pr

Use it when
a CI job has checked out a pull request and you want the agent's review as a file to publish, not comments posted directly
It does
reviews the lines the PR changes for correctness, security, error handling, performance, comment quality and tests, and labels each finding by severity
You get
review.json: an APPROVE or REJECT verdict, a review body with an overview, issue counts and a recommendation, and inline comments, with suggestion blocks for code changes
Needs
a line-annotated pr_diff.txt and pr_description.txt from your workflow, and Python 3 to run its bundled validator

Skill 1 of 2 in the Warp PR review bundle · After it: check-impl-against-spec

Expects a workflow to supply pr_diff.txt with line annotations; it writes review.json and never posts to GitHub itself.

TLDR

Built for an automated review step. The workflow checks out the PR and supplies pr_diff.txt, with every line annotated by its old or new line number, plus pr_description.txt. The agent puts correctness, security, error handling and real performance issues first, and treats comment and test quality as equal priorities, judged by the repo's own conventions. Every comment starts with a label: CRITICAL, IMPORTANT, SUGGESTION, or NIT, which is allowed only with a suggestion block. Line numbers are copied from the annotations; feedback on untouched code goes in the review body. Suggestion blocks must replace exactly the lines they target and keep brackets balanced. Before choosing a verdict, it lists every comment and test the diff adds and checks each against the repo's guidelines. It applies a repo's review-pr-local skill when one exists and, when spec_context.md is present, checks the code against the spec with a check-impl-against-spec skill if available. review.json must pass the bundled validator before it's done.
