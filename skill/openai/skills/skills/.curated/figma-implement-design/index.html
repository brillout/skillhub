figma-implement-design

Use it when
you have a link to a Figma frame or component and want it built in your codebase to match the design
It does
fetches the node's design context, a screenshot and its assets through the Figma MCP server, then rewrites Figma's React and Tailwind output in your project's conventions
You get
components that reuse or extend your existing ones and use your tokens, validated against the screenshot for layout, type, color, states, responsiveness, assets and accessibility
When they conflict
your design-system tokens win over raw Figma values, with spacing or sizes adjusted minimally to keep the look, and deviations explained in code comments
Not for
editing the Figma file itself, building screens in Figma or writing Code Connect mappings: it sends those to the repo's other Figma skills

Needs the Figma MCP server connected and access to the Figma file; with the figma-desktop server, the Figma desktop app open with a node selected.

TLDR

A design-to-code workflow from OpenAI's catalog of Codex skills, built on the Figma MCP server. From a Figma URL the agent extracts the file key and node ID; with the figma-desktop server it uses the node selected in the open file instead. It fetches the node's structured design context (layout, typography, colors, tokens, variants, spacing), falling back to a metadata map and child-by-child fetches when the response is too large, then a screenshot that stays the source of truth throughout. Images and SVGs come from the server's localhost asset endpoint: no new icon packages, no placeholders. Figma's output, usually React with Tailwind, is treated as a description of design and behavior, not as code to keep: the agent reuses your existing components, extending one rather than duplicating it, maps Figma values to your color, type and spacing tokens, and follows your routing, state and data-fetching patterns. New components get typed props and JSDoc comments. Before finishing it validates against the screenshot, including hover, active and disabled states, responsive constraints and WCAG accessibility. The openai/skills repository is marked deprecated; its README points to openai/plugins for current Codex skills.
