security-best-practices

Use it when
you explicitly ask for secure-by-default code, a security review or a security report on a Python, JavaScript/TypeScript or Go project
It does
identifies every language and framework in scope, frontend and backend, and reads the skill's matching security guides before it writes or reviews
Three modes
writes secure code from then on, flags only high-impact issues while you work, or audits the whole codebase when you ask
You get
security_best_practices_report.md: an executive summary, numbered findings by severity with line numbers, then fixes one finding at a time once you agree
Careful with
TLS: it doesn't report missing TLS as a flaw, sets secure cookies only for apps served over TLS, and avoids recommending HSTS, which it calls dangerous

TLDR

A security skill from OpenAI's catalog of Codex skills. It first works out every language and framework the project uses, then reads the guides in its references folder that match, named by language, framework and stack, plus a general guide for the language; for a web app it checks both frontend and backend. With no matching guide it falls back on well-known practices and, in a report, says that concrete guidance wasn't available. From there it either writes secure-by-default code, quietly watches for major vulnerabilities while working on your code, or produces a full report: an executive summary, findings grouped by severity with numeric IDs, line numbers and a one-sentence impact for critical ones, saved to security_best_practices_report.md unless you choose another place. Fixes come one finding at a time, after you agree, each with a short comment on the practice behind it, a check for regressions, and your usual tests and commit flow, without bundling unrelated findings into one commit. It follows project documentation that overrides a practice rather than fighting you. It doesn't trigger for general code review. The openai/skills repository is marked deprecated; its README points to openai/plugins for current Codex skills.
