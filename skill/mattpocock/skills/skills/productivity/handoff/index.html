Use it when
the work has to move to another tool, another folder, a colleague or a side session
It does
summarizes the conversation into one Markdown file a fresh agent can continue from
You get
a handoff file in your system's temp folder, ending with the skills the next agent should load

Skill 8 of 24 in the Engineering workflow bundle · Before it: research · After it: prototype

TLDR

The agent writes up the current conversation so another agent can pick up the work. The file goes to the OS temp folder ($TMPDIR or /tmp, %TEMP% on Windows), not your project. It links to specs, plans, ADRs, issues, commits and diffs by path or URL instead of copying them, strips API keys, passwords and personal information, and lists the skills the next agent should load. If you say what the next session will focus on, the summary is tailored to it. To carry on in the same tool and folder, the bundle suggests compacting the conversation instead.

Frontmatter
name: handoff
description: Compact the current conversation into a handoff document for another agent to pick up.
argument-hint: "What will the next session be used for?"
disable-model-invocation: true

Write a handoff document summarising the current conversation so a fresh agent can continue the work. Save to the temporary directory of the user's OS ($TMPDIR, else /tmp; %TEMP% on Windows) - not the current workspace.

Include a "suggested skills" section in the document, naming which skills the next agent should call the Skill tool for.

Do not duplicate content already captured in other artifacts (specs, plans, ADRs, issues, commits, diffs). Reference them by path or URL instead.

Redact any sensitive information, such as API keys, passwords, or personally identifiable information.

If the user passed arguments, treat them as a description of what the next session will focus on and tailor the doc accordingly.
