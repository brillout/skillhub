playwriter

Use it when
a site is JavaScript-heavy or behind a login, cookie wall or infinite scroll, or you want the agent in the browser you're signed in to
It does
runs Playwright snippets in a stateful sandbox connected to your Chrome, checking the URL, an accessibility snapshot and console logs after every action
First
the agent reads the whole guide that playwriter skill prints, once per session; the SKILL.md itself only points to it
Also
headless Chrome, direct CDP connections, control of a browser someone shares with you, cloud browsers, and recording what you do to turn it into a skill
Unlike
Playwright MCP servers that launch a fresh browser, it attaches to the Chrome you're already using
Needs
the playwriter CLI and its Chrome extension, enabled on the tabs it may use

It acts in your own logged-in Chrome on the tabs where you enable its extension. Its optional cloud browsers, with stealth patches, CAPTCHA solving and residential proxies, need a Playwriter account.

TLDR

The SKILL.md only tells the agent to run playwriter skill and read every line it prints, a long guide kept in the repo; this summary follows that guide. Each task gets its own session, a sandbox whose state object persists between calls, and its own Chrome tab group. The agent opens or picks a tab and follows observe, act, observe: print the URL, an accessibility snapshot and new console logs, take one action, check again. Its rules include never closing the browser, clicking a field before typing, preferring snapshots to screenshots and proper waits to fixed timeouts. Helpers cover snapshots, layout inspection, page logs, labelled screenshots, network interception and low-level mouse and keyboard control. Beyond your own Chrome it can launch headless Chrome, connect to any CDP endpoint, drive a browser someone shares through a secret remote-control id, or start cloud browsers that solve Turnstile, reCAPTCHA and hCaptcha, hide automation signals and route through residential proxies. A recorder captures your clicks, typing and network requests so the agent can turn the workflow into a reusable skill. The sandbox's own fs writes only to the working directory and temp folders, but modules it imports run with full Node.js permissions.

From remorses/playwriter at 2cae912. Checked daily, last changed Nov 7, 2026.

Frontmatter
name: playwriter
description: Control the user own Chrome browser via Playwriter extension with Playwright code snippets in a stateful local js sandbox. Use this over other Playwright MCPs to automate the browser — it connects to the user's existing Chrome instead of launching a new one. Use this cli for navigating JS-heavy websites (Instagram, Twitter, cookie/login walls, lazy-loaded UIs) instead of webfetch/curl. ALWAYS load this skill before using any playwriter commands

Read Full Documentation (once per session)

Before the first playwriter command in a session, run:

playwriter skill # IMPORTANT! do not use | head here. read in full!

This outputs the complete documentation including:

  • Session management and timeout configuration
  • Selector strategies (and which ones to AVOID)
  • Rules to prevent timeouts and failures
  • Best practices for slow pages and SPAs
  • Context variables, utility functions, and more

Do NOT skip this step. The examples below will fail without understanding timeouts, selector rules, and pitfalls from the full docs. You only need to do this once per session; subsequent playwriter commands in the same session do not require re-reading.

Read the ENTIRE output. Do NOT pipe through head, tail, or any truncation command. Critical rules are spread throughout the document, not just at the top.

Minimal Example (after reading full docs)

playwriter session new
playwriter -s 1 -e 'state.page = await context.newPage(); await state.page.goto("https://example.com")'

Always use single quotes for the -e argument. Single quotes prevent bash from interpreting $, backticks, and backslashes inside your JS code. Use double quotes or backtick template literals for strings inside the JS.

If playwriter is not found, use npx playwriter@latest or bunx playwriter@latest.
