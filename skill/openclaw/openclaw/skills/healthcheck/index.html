healthcheck

Use it when
you want to know how exposed the machine running OpenClaw is, and lock it down without cutting off your own access
It does
works out the host's setup, asking only for what's missing, runs read-only checks once you allow them, then asks which posture you want: convenience, balanced or strict
You get
a report of the current posture, findings with severity and evidence, a staged reversible plan, commands, and what it couldn't check
Checks
OpenClaw's security audit, gateway status and doctor lint, plus listening ports, firewall, SSH, updates, disk encryption and backups on macOS, Linux or Windows
Changes
nothing without your confirmation; SSH, firewall and remote access stay untouched until your access path is confirmed

Built for hosts running OpenClaw: its checks start with the openclaw CLI's security audit, gateway status and doctor commands.

TLDR

A security review for the host OpenClaw runs on, whether a personal workstation, a local assistant box or a remote server. The agent first works out what it can: the OS, whether it's in a container, its privileges, how you reach it (locally, over SSH, RDP or a tailnet), its network exposure, the OpenClaw gateway's bind and auth, backups, disk encryption and automatic updates, asking you only for what's missing. With your permission it runs read-only checks, from openclaw security audit --deep to the OS's firewall, listening ports and encryption status. It then reports and offers only the hardening items that apply, such as binding the gateway to loopback, LAN or tailnet on purpose, requiring auth for remote access, closing public ports, enabling updates and disk encryption, verifying backups, requiring SSH keys, and scheduling the audit. It prefers reversible steps with rollback notes, never prints secrets, only recommends when it doesn't know your role, and never claims OpenClaw manages the firewall, SSH or updates.

OpenClaw host healthcheck

Goal: assess host risk, run read-only checks, then propose staged hardening without breaking access.

Rules

  • Ask before state-changing actions.
  • Do not change SSH/firewall/remote access until access path is confirmed.
  • Prefer reversible steps and rollback notes.
  • Never claim OpenClaw manages OS firewall, SSH, or updates.
  • If identity/role unknown, recommend only.
  • User choices: numbered list.
  • Never print secrets.

Context to infer first

  • OS/version, container vs host.
  • Privilege level.
  • Access path: local, SSH, RDP, tailnet.
  • Network exposure: public IP, reverse proxy, tunnel, LAN only.
  • OpenClaw gateway status, bind, auth.
  • Backup status.
  • Disk encryption.
  • Automatic security updates.
  • Usage mode: personal workstation, local assistant box, remote server, other.

Ask only for missing facts. Simple phrasing preferred.

Read-only checks

Ask once for permission to run read-only checks. Then run relevant commands.

Common:

openclaw security audit --deep
openclaw gateway status --deep
openclaw doctor --lint

doctor --lint can exit 1 for findings: read the report and continue the remaining checks. Ordinary doctor and doctor --non-interactive can copy legacy config and migrate state without --fix; reserve repairs for explicit approval. Read-only checks exclude config/service repairs and state migrations, but may produce incidental logs or cache bookkeeping.

macOS:

sw_vers
lsof -nP -iTCP -sTCP:LISTEN
/usr/libexec/ApplicationFirewall/socketfilterfw --getglobalstate
pfctl -s info
tmutil status
fdesetup status
softwareupdate --schedule

Linux:

cat /etc/os-release
ss -ltnup || ss -ltnp
ufw status || firewall-cmd --state || nft list ruleset
systemctl status ssh sshd
lsblk -f

Windows:

systeminfo
Get-NetFirewallProfile
Get-BitLockerVolume

Risk profile

After context is known, ask desired posture:

  1. Convenience: local/private, minimal prompts.
  2. Balanced: secure defaults, low friction.
  3. Strict: remote/public/sensitive data, more lock-down.

Report shape

  • Current posture: one paragraph.
  • Findings: severity + evidence + why it matters.
  • Recommended plan: staged, reversible.
  • Commands: read-only first; write actions only after approval.
  • Gaps: what could not be checked.

Hardening menu

Offer only relevant items:

  • Bind gateway to loopback/LAN/tailnet intentionally.
  • Require auth for remote access.
  • Close public ports or restrict by firewall.
  • Enable OS security updates.
  • Enable disk encryption.
  • Verify backups and restore path.
  • Disable password SSH or require keys/MFA where appropriate.
  • Add scheduled openclaw security audit --deep.

Confirm exact action before applying.
