skill-creator

Use it when
you want to write a new skill for OpenClaw, or review, repair or restructure an existing SKILL.md and its files
It does
walks five steps, each closed by a "done when" check: list each distinct case the skill handles, pick how it's invoked, lay out its files, draft, validate
You get
a SKILL.md with references/, scripts/ and assets/ as needed, as a pending proposal in OpenClaw's skill_workshop tool or a diff in your repo
Validates with
a bundled Python script that checks the frontmatter: only allowed keys, a hyphen-case name, and a description of at most 1,024 characters without angle brackets
Unlike
Anthropic's skill-creator, it runs no evals: it's a short checklist built around OpenClaw's frontmatter fields and its skill_workshop tool

Built for OpenClaw: live skills are drafted with OpenClaw's skill_workshop tool, and its validator rejects frontmatter keys OpenClaw doesn't support.

TLDR

OpenClaw's own guide to authoring skills in the AgentSkills format. It starts by pinning down the contract: each real branch of the workflow, as opposed to a synonym for another, gets a trigger, an expected outcome and a place where its result is saved. Then it picks how the skill is reached: found by the model through its description, run only by hand with disable-model-invocation, or dispatched straight to a tool without the model. Shared steps go in SKILL.md, each ending with a checkable completion criterion; branch-only detail goes to references/, helpers to scripts/, output resources to assets/ and UI metadata to agents/. A live workspace skill is drafted as a pending proposal in OpenClaw's skill_workshop tool, leaving the live files untouched until it's applied; a skill kept in a repository goes through that repo's normal edit and review. Last, it runs quick_validate.py on the skill folder, plus the focused test of every helper it touched. The validator accepts only the frontmatter fields OpenClaw supports, such as metadata, homepage, user-invocable and command-dispatch, and rejects any other key.

Skill Creator

Workflow

  1. Establish the contract.

    • Read the existing skill and its resources, or collect concrete requests for a new skill.
    • Separate actual workflow branches from synonyms for the same branch.
    • Done when: every branch has a concrete trigger, expected outcome, and persistence target.

  2. Choose invocation.

    • Model-discoverable: write a model-facing description; omit disable-model-invocation.
    • Manual-only: set disable-model-invocation: true; write a human-facing summary.
    • Direct tool command: add command-dispatch: tool, command-tool, and command-arg-mode only when the command bypasses the model.
    • Done when: frontmatter matches how the skill will actually be reached.

  3. Structure the skill.

    • Map shared ordered procedure to SKILL.md; end every step with a checkable completion criterion and finish with verification.
    • Keep routing conditions in description; start the body with execution.
    • Map branch-only detail to references/, repeatable helpers to scripts/, output resources to assets/, and optional UI metadata to agents/.
    • Done when: every planned resource has one purpose and a direct pointer from SKILL.md.

  4. Draft and persist.

    • Live workspace skill: use skill_workshop to create or revise a pending proposal; keep live files unchanged until apply.
    • Repository-owned skill source: use the repository's normal edit and review workflow.
    • Done when: the proposal or source diff implements every branch from step 1 and contains every resource from step 3.

  5. Validate.

    • Run python {baseDir}/scripts/quick_validate.py <skill-directory> and execute every touched helper's focused test.
    • Done when: frontmatter passes, resource pointers resolve, and every touched helper passes its focused test.

Frontmatter

Required: name, description.

OpenClaw also supports metadata, homepage, license, allowed-tools, user-invocable, disable-model-invocation, command-dispatch, command-tool, and command-arg-mode. Add optional fields only when they change runtime behavior or discovery.
