orca-emulator

Use it when
you work in Orca and an iOS change needs checking on a simulator, or the agent must use an app there
It does
attaches a simulator to your worktree, then taps, types, swipes, presses buttons and rotates through Orca's emulator commands, finding targets in the accessibility tree
You get
a device the agent drives while you watch it live in Orca's emulator pane
Needs
Orca on a Mac with the Xcode Command Line Tools, and the app already built and installed with xcodebuild or simctl
Unlike orca-emulator-android
which drives Android devices over adb and can also install apps, grant permissions and read logcat

Needs Orca, Stably's desktop app for running coding agents in parallel, on a Mac with the Xcode Command Line Tools.

TLDR

Orca is Stably's desktop app for running many coding agents in parallel. The SKILL.md is a short stub: it picks the right Orca executable, warning that on Linux a bare orca command outside Orca's terminals usually starts the GNOME screen reader, then loads the guide that matches the installed Orca version. That guide maps each goal to an orca emulator command: list devices and sessions, attach a simulator and make it active for the worktree, tap, gesture, type, press home or the side button, rotate, read the accessibility tree, pass any other command straight to serve-sim, the simulator tool Orca wraps, and stop the helper or shut the simulator down. Coordinates run from 0 to 1 from the top left, so the agent taps an element at its frame's center, and typing is ASCII only. It tells the agent to stop the helper when done, since it holds the device until Orca quits, and how to get input working again when Xcode's Device Hub blocks it.

Orca Emulator

This discovery stub loads the version-matched guide from the Orca executable used for this session.

Prefer Orca over raw serve-sim or direct simctl for simulator control inside Orca; it handles device scoping, helper lifecycle, and worktree context.

Resolve the CLI for this session

Choose the executable once and reuse it for every later command:

  • If the ORCA_CLI_COMMAND environment variable is set, use its value. Orca exports this for managed WSL sessions.
  • Otherwise, in a dev checkout whose session exposes ORCA_DEV_REPO_ROOT, use orca-dev.
  • Otherwise, on Linux outside an Orca-managed terminal, use orca-ide. Never run bare orca there — outside Orca's terminals it normally resolves to the GNOME Orca screen reader (/usr/bin/orca) and starts speech on the user's machine.
  • Otherwise, use orca.
