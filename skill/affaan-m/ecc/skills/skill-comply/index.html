skill-comply

Use it when
you've written a skill or rule and want to know whether the agent follows it, rather than assume it does
It does
derives the expected steps from the file, writes scenarios at three prompt strictness levels, runs each with claude -p and classifies the tool calls
You get
a Markdown report with the spec, the prompts, a compliance score per scenario and a labelled timeline of tool calls
Needs
Claude Code and uv; full runs spend tokens on every scenario, while a dry run stops after the cheaper model writes the spec and scenarios
Works on
SKILL.md files, rule files and agent definitions, the last only for whether the agent gets invoked when expected

Runs Claude Code headless once per scenario, working in a temporary folder with Bash and file edits pre-approved (nothing confines Bash to that folder), which spends tokens. Needs uv.

TLDR

skill-comply tests instructions the way you'd test code. Given a skill, rule or agent file, its bundled Python script has a cheaper model, Haiku by default, extract the expected sequence of steps, then write scenarios whose prompts go from supportive to neutral to competing, so you can see whether the instruction holds even when the prompt doesn't back it. Each scenario runs in a fresh sandbox folder through Claude Code's headless mode, Sonnet by default, with its tool calls captured as stream-json. An LLM, not a regex, matches the calls to the expected steps, and their order is checked deterministically. The report holds the spec, the scenario prompts, each scenario's compliance score and the tool-call timeline with labels, and for steps with low compliance it suggests turning them into hooks. A --dry-run flag prints the spec and scenarios and skips the scenario runs, so only the generation model is called, and --model and --gen-model pick the models.

skill-comply: Automated Compliance Measurement

Measures whether coding agents actually follow skills, rules, or agent definitions by:

  1. Auto-generating expected behavioral sequences (specs) from any .md file
  2. Auto-generating scenarios with decreasing prompt strictness (supportive → neutral → competing)
  3. Running claude -p and capturing tool call traces via stream-json
  4. Classifying tool calls against spec steps using LLM (not regex)
  5. Checking temporal ordering deterministically
  6. Generating self-contained reports with spec, prompts, and timelines

Supported Targets

  • Skills (skills/*/SKILL.md): Workflow skills like search-first, TDD guides
  • Rules (rules/common/*.md): Mandatory rules like testing.md, security.md, git-workflow.md
  • Agent definitions (agents/*.md): Whether an agent gets invoked when expected (internal workflow verification not yet supported)

When to Activate

  • User runs /skill-comply <path>
  • User asks "is this rule actually being followed?"
  • After adding new rules/skills, to verify agent compliance
  • Periodically as part of quality maintenance

Usage

# Full run
uv run python -m scripts.run ~/.claude/rules/common/testing.md

# Dry run (no cost, spec + scenarios only)
uv run python -m scripts.run --dry-run ~/.claude/skills/search-first/SKILL.md

# Custom models
uv run python -m scripts.run --gen-model haiku --model sonnet <path>

Key Concept: Prompt Independence

Measures whether a skill/rule is followed even when the prompt doesn't explicitly support it.

Report Contents

Reports are self-contained and include:

  1. Expected behavioral sequence (auto-generated spec)
  2. Scenario prompts (what was asked at each strictness level)
  3. Compliance scores per scenario
  4. Tool call timelines with LLM classification labels
Advanced (optional)

For users familiar with hooks, reports also include hook promotion recommendations for steps with low compliance. This is informational — the main value is the compliance visibility itself.
