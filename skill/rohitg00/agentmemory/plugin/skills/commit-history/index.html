commit-history

Use it when
you want to see what the agent has shipped: commits alongside the sessions that produced them
It does
lists the git commits linked to agent sessions in agentmemory, filtered by branch or repo if you ask, up to 100 by default and 500 at most
You get
newest first: short sha, branch, date, first line of the message, linked session ids with observation counts, and file counts
Needs

Unlike commit-context

TLDR

Part of agentmemory, a memory server that records what coding agents do in each session as observations. commit-history lists the git commits linked to those sessions. You can filter by branch and by repository URL or a fragment of it, and set a limit; a bare number is the limit, and by default there's no filter and up to 100 commits, capped at 500. The list shows only what the tool returned, newest first, with the short sha, branch, authored time, first line of the message, the linked sessions' short ids with their observation counts, and the number of files when given. An empty result means the filter matched nothing, and the agent suggests dropping the branch or repo filter. When the MCP tools are missing and it calls agentmemory's REST API instead, it URL-encodes every filter value.

SKILL.md

From rohitg00/agentmemory at f0f7378. Checked daily, last changed Nov 6, 2026.

Frontmatter
name: commit-history
description: List recent git commits linked to agent sessions, optionally filtered by branch or repo. Use when the user asks "show agent commits", "what has the agent shipped", "list linked commits", or wants commits with their session context.
argument-hint: "[branch=... repo=... limit=...]"
user-invocable: true

The user wants a list of agent-linked commits. Filter args: $ARGUMENTS

Quick start

memory_commits { "branch": "main", "limit": 20 }

Expected output:

9a1b2c3 main 2026-06-07 "rotate refresh tokens" · session 7f3a9c2 (14 obs)
b21d004 main 2026-06-05 "rate limiter audit"    · session b21d004 (9 obs)

Why

Render only the commits the tool returned, newest first. An empty result means the filter matched nothing, not that work is missing.

Workflow

  1. Parse $ARGUMENTS for branch=<name>, repo=<url-or-fragment>, limit=<n>. A bare numeric token is the limit. Defaults: no branch, no repo, limit 100, max 500.
  2. Call memory_commits with the parsed filters.
  3. Render reverse-chronologically: short sha, branch, authored timestamp, first line of the message, linked session id(s) (first 8) with observation counts, and file count when files is present.
  4. Empty result: tell the user the filter matched nothing and suggest dropping the branch or repo filter.

Anti-patterns

WRONG (REST fallback): concatenate ?branch= + raw branch name, so a name with ?, &, or # corrupts the query string.

RIGHT: URL-encode every value with URLSearchParams/encodeURIComponent before appending to GET /agentmemory/commits.

Checklist

  • Filters parsed; bare number treated as limit; limit capped at 500.
  • Output is reverse-chronological.
  • Session ids and observation counts come straight from the response.
  • REST fallback URL-encodes branch, repo, and limit.

See also

  • commit-context: drill into one commit's session.
  • recall: search the observations behind a linked session.

Troubleshooting

See TROUBLESHOOTING.md if memory_commits is not available.
