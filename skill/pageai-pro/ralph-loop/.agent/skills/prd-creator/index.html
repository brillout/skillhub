TLDR

A two-part planning skill aimed at beginner developers. Part one turns a thin description into a PRD: the agent asks clarifying questions with AskUserQuestion, checks prerequisites such as access, MCP servers, docs, environment variables and test users, adds placeholder entries for missing values to .env.local, and shows an executive summary for your approval. It then researches the competition on the web and writes the PRD: overview and objectives, audience, success metrics, competitive analysis, core features and user flows, a recommended stack, prerequisites, security, assumptions and dependencies. Part two, once you approve, breaks the PRD into tasks: an index in tasks.json and a spec file per task. TASK-1 always verifies the prerequisites, each later task should take ten minutes at most, carries a category such as functional, ui-ux, api-endpoint or security, and has pass steps that verify it, and every task starts as not passed. A short SUMMARY.md describes the project, its main features, key flows and requirements. You can update the PRD or the tasks later, and at the end it checks that all three files exist.
