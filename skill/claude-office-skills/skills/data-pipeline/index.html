data-pipeline

Use it when
you need to move data between apps, databases and a warehouse or spreadsheet on a schedule, such as daily sales into BigQuery
It does
plans each stage: extract from databases, APIs, files or SaaS apps; clean, map, aggregate and enrich; load to warehouses, databases, storage, sheets or webhooks
You get
a pipeline spec with schedule, retries, extract settings, a JavaScript transform, destinations, quality checks and alert channels, like its daily Shopify-and-Stripe sales example
Also covers
cron schedules, dependencies, retries with exponential backoff, alerts on failures, row-count anomalies and stale data, and schema, null-rate and business-rule checks
Doesn't
run anything: it says it's based on n8n templates, but its workflows are YAML outlines and the data-mcp tools in its frontmatter are never called

TLDR

From Claude Office Skills. You describe the data you have and where it should end up, and the agent designs the pipeline from its patterns. Sources include PostgreSQL, MySQL and MongoDB, REST and GraphQL APIs, CSV, Excel and JSON files, and Salesforce, HubSpot, Stripe and Shopify; destinations include BigQuery, Snowflake, Redshift, Postgres, MySQL, S3, Google Cloud Storage, Google Sheets, Airtable and webhooks. Transformations are listed by kind (cleaning, mapping, aggregation, enrichment, filtering), with JavaScript functions that normalize records and total them by date and category. Its monitoring tracks rows processed, run time, errors and freshness, and posts failures to Slack or PagerDuty. Quality checks validate required fields, types and allowed values, keep null and duplicate rates low, test business rules such as totals matching line items, and flag row counts more than two standard deviations from the mean.

Code Transform Examples
// Clean and normalize data
function transform(items) {
  return items.map(item => ({
    // Clean strings
    name: item.name?.trim().toLowerCase(),
    
    // Parse dates
    date: new Date(item.created_at).toISOString().split('T')[0],
    
    // Convert types
    amount: parseFloat(item.amount) || 0,
    
    // Map values
    status: statusMap[item.status_code] || 'unknown',
    
    // Calculate fields
    total: item.quantity * item.unit_price,
    
    // Filter nested
    tags: item.tags?.filter(t => t.active).map(t => t.name),
    
    // Default values
    source: item.source || 'direct'
  }));
}

// Aggregate data
function aggregate(items) {
  const grouped = {};
  
  items.forEach(item => {
    const key = `${item.date}_${item.category}`;
    if (!grouped[key]) {
      grouped[key] = {
        date: item.date,
        category: item.category,
        total_revenue: 0,
        order_count: 0
      };
    }
    grouped[key].total_revenue += item.amount;
    grouped[key].order_count += 1;
  });
  
  return Object.values(grouped);
}

Data Quality

Quality Checks
data_quality:
  schema_validation:
    - required_fields: [id, date, amount]
    - field_types:
        id: integer
        date: date
        amount: number
    - allowed_values:
        status: [active, pending, closed]
        
  statistical_checks:
    - null_rate: < 5%
    - duplicate_rate: < 1%
    - value_range:
        amount: [0, 1000000]
        
  business_rules:
    - total_equals_sum_of_line_items
    - dates_are_not_in_future
    - email_format_valid
    
  trend_analysis:
    - row_count: within_2_std_of_mean
    - total_value: within_expected_range
