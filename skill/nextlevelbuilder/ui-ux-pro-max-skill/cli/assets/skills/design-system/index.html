TLDR

One of the design skills, written by ClaudeKit, that ship next to ui-ux-pro-max in the UI UX Pro Max repo. Tokens come in three layers: primitives hold raw values such as --color-blue-600, semantic tokens alias them by purpose such as --color-primary, and component tokens such as --button-bg point at those, so a theme can switch without touching components. generate-tokens.cjs turns a JSON config into CSS variables, validate-tokens.cjs scans your source for hardcoded values, and a starter JSON template is included. References cover each layer, component specs, states and variants, and Tailwind integration. The slide half builds persuasive HTML decks: a BM25 search over bundled CSV data picks a deck structure with an emotional arc, then for each slide a layout, type scale, color treatment and, if needed, a background image; the agent writes the HTML on the tokens and checks it with a validator script. Every slide must import the tokens CSS, use only CSS variables, draw charts with Chart.js and include navigation.

Token Architecture

Load: references/token-architecture.md

Three-Layer Structure
Primitive (raw values)
       ↓
Semantic (purpose aliases)
       ↓
Component (component-specific)

Example:

/* Primitive */
--color-blue-600: #2563EB;

/* Semantic */
--color-primary: var(--color-blue-600);

/* Component */
--button-bg: var(--color-primary);

        ↓

Pattern Breaking (Duarte Sparkline)

Premium decks alternate between emotions for engagement:

"What Is" (frustration) ↔ "What Could Be" (hope)

System calculates pattern breaks at 1/3 and 2/3 positions.

Slide Requirements

ALL slides MUST:

  1. Import assets/design-tokens.css - single source of truth
  2. Use CSS variables: var(--color-primary), var(--slide-bg), etc.
  3. Use Chart.js for charts (NOT CSS-only bars)
  4. Include navigation (keyboard arrows, click, progress bar)
  5. Center align content
  6. Focus on persuasion/conversion

Token Compliance
/* CORRECT - uses token */
background: var(--slide-bg);
color: var(--color-primary);
font-family: var(--typography-font-heading);

/* WRONG - hardcoded */
background: #0D0D0D;
color: #FF6B6B;
font-family: 'Space Grotesk';

Best Practices

  1. Never use raw hex in components - always reference tokens
  2. Semantic layer enables theme switching (light/dark)
  3. Component tokens enable per-component customization
  4. Use HSL format for opacity control
  5. Document every token's purpose
  6. Slides must import design-tokens.css and use var() exclusively
