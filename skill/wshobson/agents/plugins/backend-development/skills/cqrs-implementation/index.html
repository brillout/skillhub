TLDR

A reference for Command Query Responsibility Segregation, not a workflow. The SKILL.md diagrams the split: commands express intent to change state and go through command handlers that validate and emit events; queries read from a denormalized read model built by projectors that apply those events. Its do's and don'ts: separate the models, accept propagation delay, validate in command handlers, version events, don't query inside commands or couple the two schemas, and don't over-engineer. A reference file holds Python templates — a command base and bus with handlers, a query base and bus with paginated results, a FastAPI app wiring command endpoints (POST/PUT/DELETE) to query endpoints (GET), a read-model synchronizer that tracks a checkpoint and can rebuild a projection from scratch, and a query handler that waits for the read model to reach an expected version before returning, falling back to stale data with a warning after a timeout.

CQRS Implementation

Comprehensive guide to implementing CQRS (Command Query Responsibility Segregation) patterns.

When to Use This Skill

  • Separating read and write concerns
  • Scaling reads independently from writes
  • Building event-sourced systems
  • Optimizing complex query scenarios
  • Different read/write data models needed
  • High-performance reporting requirements

Core Concepts

2. Key Components
Component Responsibility
Command Intent to change state
Command Handler Validates and executes commands
Event Record of state change
Query Request for data
Query Handler Retrieves data from read model
Projector Updates read model from events

Best Practices

Do's
  • Separate command and query models - Different needs
  • Use eventual consistency - Accept propagation delay
  • Validate in command handlers - Before state change
  • Denormalize read models - Optimize for queries
  • Version your events - For schema evolution
Don'ts
  • Don't query in commands - Use only for writes
  • Don't couple read/write schemas - Independent evolution
  • Don't over-engineer - Start simple
  • Don't ignore consistency SLAs - Define acceptable lag
