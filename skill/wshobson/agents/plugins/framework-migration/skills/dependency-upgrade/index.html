dependency-upgrade

Use it when
you're moving a JavaScript project to a new major version of a framework or library, or clearing out outdated and vulnerable packages
It does
audits what's outdated, maps compatible versions, then upgrades in three phases, one package at a time with tests after each, rolling back if they fail
You get
an UPGRADE_PLAN.md with the upgrade order, an updated package.json and lockfile, and compatibility tests
Also covers
jscodeshift codemods for breaking changes, Renovate and Dependabot configs, lockfile commands and peer-dependency conflicts

TLDR

A staged process with npm and yarn commands, using a React upgrade as the running example. It opens with semantic versioning and the ^ and ~ ranges, then audits with npm outdated, npm audit and npm-check-updates and traces why a package is installed. A compatibility matrix records which versions of related packages go together, such as React with react-dom, React Router and Testing Library. Phase 1 lists current versions, reads changelogs and migration guides, and writes the upgrade order to UPGRADE_PLAN.md: TypeScript, then React, React Router, testing libraries and build tools. Phase 2 upgrades one package, and one major version, at a time, running tests and the build after each. Phase 3 adds tests that check matching versions and no peer-dependency warnings. Breaking changes get codemods (jscodeshift scripts that rewrite code, tried with a dry run first) or a custom find-and-replace script. Testing covers unit, integration, snapshot and Cypress end-to-end tests. A rollback script upgrades on a branch and commits only if tests pass. It ends with a Renovate config that auto-merges minor and patch updates but not majors, a weekly Dependabot config, and commands for lockfiles, peer dependencies and workspaces.

Dependency Upgrade

Master major dependency version upgrades, compatibility analysis, staged upgrade strategies, and comprehensive testing approaches.

When to Use This Skill

  • Automating dependency updates

Semantic Versioning Review

MAJOR.MINOR.PATCH (e.g., 2.3.1)

MAJOR: Breaking changes
MINOR: New features, backward compatible
PATCH: Bug fixes, backward compatible

^2.3.1 = >=2.3.1 <3.0.0 (minor updates)
~2.3.1 = >=2.3.1 <2.4.0 (patch updates)
2.3.1 = exact version

# Don't upgrade everything at once!

Custom Migration Script
// migration-script.js
const fs = require("fs");
const glob = require("glob");

glob("src/**/*.tsx", (err, files) => {
  files.forEach((file) => {
    let content = fs.readFileSync(file, "utf8");

    // Replace old API with new API
    content = content.replace(
      /componentWillMount/g,
      "UNSAFE_componentWillMount",
    );

    // Update imports
    content = content.replace(
      /import { Component } from 'react'/g,
      "import React, { Component } from 'react'",
    );

    fs.writeFileSync(file, content);
  });
});

Rollback Plan

// rollback.sh
#!/bin/bash

# Save current state
git stash
git checkout -b upgrade-branch

# Attempt upgrade
npm install package@latest

# Run tests
if npm run test; then
  echo "Upgrade successful"
  git add package.json package-lock.json
  git commit -m "chore: upgrade package"
else
  echo "Upgrade failed, rolling back"
  git checkout main
  git branch -D upgrade-branch
  npm install  # Restore from package-lock.json
fi

Common Upgrade Patterns

Lock File Management
# npm
npm install --package-lock-only  # Update lock file only
npm ci  # Clean install from lock file

# yarn
yarn install --frozen-lockfile  # CI mode
yarn upgrade-interactive  # Interactive upgrades
Peer Dependency Resolution
# npm 7+: strict peer dependencies
npm install --legacy-peer-deps  # Ignore peer deps

# npm 8+: override peer dependencies
npm install --force
Workspace Upgrades
# Update all workspace packages
npm install --workspaces

# Update specific workspace
npm install package@latest --workspace=packages/app
