TLDR

A reference with templates rather than a workflow. The SKILL.md has a 2026 table of embedding models, from voyage-3-large and OpenAI's text-embedding-3 models to open-source bge-large, all-MiniLM and multilingual-e5, and a pipeline: chunk, preprocess, embed. Its rules: match the model to code, prose or multilingual content, keep chunks on meaning boundaries, normalize vectors for cosine similarity, batch and cache requests, respect token limits, never mix models in one index, and keep metadata. The reference file holds six Python templates: Voyage AI embeddings through LangChain, including the code, finance and law models; OpenAI embeddings in batches of 100 with optional dimension reduction (Matryoshka embeddings, which still work when cut shorter); local BGE and E5 models with the query prefixes they expect; chunking by tokens, sentences, Markdown headers or a recursive splitter; a pipeline that cleans, chunks and embeds documents with metadata, and one that splits code into functions and classes with tree-sitter; and an evaluation that scores retrieval by precision, recall, MRR and NDCG and compares models side by side.

Embedding Strategies

Guide to selecting and optimizing embedding models for vector search applications.

When to Use This Skill

  • Choosing embedding models for RAG
  • Optimizing chunking strategies
  • Fine-tuning embeddings for domains
  • Comparing embedding model performance
  • Reducing embedding dimensions
  • Handling multilingual content

Best Practices

Do's
  • Match model to use case: Code vs prose vs multilingual
  • Chunk thoughtfully: Preserve semantic boundaries
  • Normalize embeddings: For cosine similarity search
  • Batch requests: More efficient than one-by-one
  • Cache embeddings: Avoid recomputing for static content
  • Use Voyage AI for Claude apps: Recommended by Anthropic
Don'ts
  • Don't ignore token limits: Truncation loses information
  • Don't mix embedding models: Incompatible vector spaces
  • Don't skip preprocessing: Garbage in, garbage out
  • Don't over-chunk: Lose important context
  • Don't forget metadata: Essential for filtering and debugging
