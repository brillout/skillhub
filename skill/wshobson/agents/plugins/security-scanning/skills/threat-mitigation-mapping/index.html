threat-mitigation-mapping

Use it when
you have a list of threats and must decide which security controls to invest in, check what they cover, or plan remediation
It does
maps each threat to controls by type (prevent, detect, correct) and by layer (network, application, data, endpoint, process), checking for defense in depth
You get
a mitigation report: executive summary, defense-in-depth coverage, critical gaps, recommendations and an implementation roadmap
Also has
Python templates for a control library tied to STRIDE threat categories (spoofing, tampering, repudiation and so on), budget-limited control selection and control effectiveness tests

TLDR

The step after finding threats: deciding what stops them. Controls are sorted by what they do, preventing an attack (firewall, input validation), detecting one in progress (intrusion detection, log monitoring) or recovering from it (incident response, backup restore), and by layer, from network and application to data, endpoints, and people and process. Defense in depth means each threat meets several layers and kinds of control, so no single control is a point of failure. Its Python templates model threats, controls and coverage; hold a library of standard controls, such as multi-factor authentication, with cost, effectiveness and compliance references; compute risk reduction and critical gaps; choose controls within a budget; generate a roadmap and a report; and test whether controls work. The rules: leave no threat unmapped, layer and mix control types, weigh cost, test controls, review them regularly, and don't rely on technology alone.

Threat Mitigation Mapping

Connect threats to controls for effective security planning.

When to Use This Skill

  • Prioritizing security investments
  • Creating remediation roadmaps
  • Validating control coverage
  • Designing defense-in-depth
  • Security architecture review
  • Risk treatment planning

Core Concepts

1. Control Categories
Preventive ────► Stop attacks before they occur
   │              (Firewall, Input validation)
   │
Detective ─────► Identify attacks in progress
   │              (IDS, Log monitoring)
   │
Corrective ────► Respond and recover from attacks
                  (Incident response, Backup restore)
2. Control Layers
Layer Examples
Network Firewall, WAF, DDoS protection
Application Input validation, authentication
Data Encryption, access controls
Endpoint EDR, patch management
Process Security training, incident response

Best Practices

Do's
  • Map all threats - No threat should be unmapped
  • Layer controls - Defense in depth is essential
  • Mix control types - Preventive, detective, corrective
  • Track effectiveness - Measure and improve
  • Review regularly - Controls degrade over time
Don'ts
  • Don't rely on single controls - Single points of failure
  • Don't ignore cost - ROI matters
  • Don't skip testing - Untested controls may fail
  • Don't set and forget - Continuous improvement
  • Don't ignore people/process - Technology alone isn't enough
