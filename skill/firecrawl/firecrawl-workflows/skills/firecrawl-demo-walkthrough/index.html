firecrawl-demo-walkthrough

Use it when
you're preparing a product demo, doing a UX teardown, or studying a product's signup, onboarding, pricing, docs or dashboard experience
It does
opens the product in Firecrawl's browser, navigates each flow, takes a snapshot at every step and records what you see and can do
You get
a walkthrough: product overview, numbered steps per flow, first impressions, friction points, UX and product recommendations, pages visited and rerun inputs
Needs
the Firecrawl CLI and a Firecrawl API key; credentials if protected areas are in scope
Asks first
won't submit real credentials, make purchases or take irreversible actions unless you explicitly tell it to and have permission

TLDR

It infers the product URL and which flows to cover (full, signup, pricing, docs or dashboard) and asks up to three questions only when blocked. Where the agent can run subagents, separate walkers can take the homepage and marketing, signup and onboarding, pricing, docs and developer experience, the dashboard and core product, and help and support, each returning screens visited, actions taken, observations, friction and URLs. The write-up names specific screens, calls to action, forms and transitions, and keeps observation apart from opinion.

Firecrawl Demo Walkthrough

Use this to document a product experience step by step.

Onboarding Interview

Infer the product URL, flow focus, and output format from context. If the URL is clear, proceed immediately.

Ask at most 1-3 concise questions only if blocked, such as the URL, desired flow focus, or credentials/constraints for protected areas.

Firecrawl Collection Plan

Use Firecrawl browser to open the product and navigate key flows. Snapshot at each step, scrape pages when useful, and document what the user sees and can do.

Do not submit real credentials, purchases, or irreversible actions unless the user explicitly instructs and has permission.

Parallel Work

If appropriate, use sub-agents or equivalent parallel task runners:

  • Homepage and Marketing
  • Signup and Onboarding
  • Pricing and Plans
  • Docs and Developer Experience
  • Dashboard and Core Product
  • Help and Support

Each walker should return screens visited, actions taken, observations, friction, and source URLs.
