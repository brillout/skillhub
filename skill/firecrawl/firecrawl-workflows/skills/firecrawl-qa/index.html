firecrawl-qa

Use it when
you want a pre-launch check, a bug hunt or confirmation that a deployed site works
It does
maps the site's pages, then tests links, forms, content, layouts, error states or performance in Firecrawl's browser, with testers that can run as parallel subagents
You get
a QA report: a health score out of 10, critical, major and minor issues, steps to reproduce the serious ones, what works well, pages tested and rerun inputs
Needs
the Firecrawl CLI and a Firecrawl API key; credentials if you want protected flows tested
Unlike webapp-testing
it tests a deployed site through Firecrawl's browser; Anthropic's webapp-testing writes Playwright scripts against an app on your machine

Skill 10 of 16 in the Firecrawl Workflows bundle · Before it: firecrawl-seo-audit · After it: firecrawl-demo-walkthrough

TLDR

You give a URL and optionally a focus: full, forms, navigation, responsive or performance. Each focus splits into four testers. A full run covers navigation and links, forms and interactions, content and visuals, and error states; a forms run covers discovery, the happy path, edge cases and validation; navigation covers the sitemap, menus, links and routing; responsive covers desktop, tablet, mobile and interaction; performance covers page load, assets, content efficiency and comparison. Each tester returns severity, URL, description, evidence and steps to reproduce. The report merges duplicate findings across testers and leaves out speculative bugs without evidence. The result is a report, not fixes.

Firecrawl QA

Use this to test a live site and return a unified QA report.

Onboarding Interview

Infer the URL, QA focus, and output format from context. If the target URL is clear, proceed immediately.

Ask at most 1-3 concise questions only if blocked, such as the URL, the focus area, or credentials/constraints for protected flows.

Firecrawl Collection Plan

Use Firecrawl map to discover pages. Use Firecrawl browser for interactions, forms, navigation, and responsive/manual checks when available. Use scrape for page content and link extraction.

Parallel Work

If appropriate, use sub-agents or equivalent parallel task runners:

  • Full: Navigation and Links, Forms and Interactions, Content and Visual, Error States.
  • Forms: Form Discovery, Happy Path, Edge Cases, Validation.
  • Navigation: Sitemap, Nav Testing, Link Checker, Routing.
  • Responsive: Desktop, Tablet, Mobile, Interaction.
  • Performance: Page Load, Asset Audit, Content Efficiency, Comparison.

Each tester should return severity, URL, description, evidence, and reproduction steps.

Quality Bar

  • Include reproduction steps for functional issues.
  • Do not report speculative bugs without evidence.
  • Deduplicate findings across testers.
