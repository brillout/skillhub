firecrawl-knowledge-base

Use it when
you want web docs or a topic collected as local files for reference, retrieval by an AI (RAG), fine-tuning or a Markdown mirror of a docs site
It does
maps documentation sites or searches a topic with Firecrawl, scrapes pages into Markdown with code and tables kept, and files them by host and path
You get
files under .firecrawl/ plus, depending on the goal, sources.json, chunk files and a manifest, or training JSONL, and a summary of coverage
Needs
the Firecrawl CLI and a Firecrawl API key
Unlike firecrawl-knowledge-ingest
that one clicks through JavaScript-heavy or login-gated docs portals in a browser; this one maps and scrapes pages

TLDR

It turns URLs or topics into content an AI model can use. You say the source and the goal, and it picks one of four outputs: reference (Markdown files with an index.md and sources.json), RAG (Markdown plus chunk files and a manifest.json, for retrieval-augmented generation, where a model looks up passages before answering), training (the scraped files plus training-data.jsonl and its metadata, for fine-tuning) or a docs mirror (a complete Markdown copy with a table of contents). For documentation sites it lists the site's URLs first; for topics it searches. Pages are saved as .firecrawl/<host>/<path>/index.md, with navigation boilerplate removed where possible, code examples and formatting kept, and source URLs in each file's metadata. It asks up to three questions only when the source, goal or training format is unclear. Work can be split across subagents by docs section or source type. It ends with a summary of what was collected, the file structure, coverage counts, usage notes and rerun inputs.

Firecrawl Knowledge Base

Use this to turn URLs or topics into organized LLM-ready content.

Onboarding Interview

Infer the source, goal, depth, and output location from context. If the source and goal are clear, proceed immediately.

Ask at most 1-3 concise questions only if blocked, such as the source URL/topic, whether the output is reference/RAG/training/docs, or training format if training is requested.

Firecrawl Collection Plan

Use Firecrawl map for documentation sites, search for topic-based corpora, scrape pages into markdown, and preserve code examples and tables.

For files, follow the Firecrawl download-style convention:

.firecrawl/
  <hostname>/
    <path>/
      index.md

Parallel Work

If appropriate, use sub-agents or equivalent parallel task runners:

  • one docs section per researcher
  • official docs, tutorials, community discussions, and references by source type
  • source scraping vs chunk generation vs manifest generation

Output Modes

  • Reference: markdown files, index.md, and sources.json.
  • RAG: markdown files plus chunk files and manifest.json.
  • Training: scraped source files plus training-data.jsonl and training-metadata.json.
  • Docs mirror: complete markdown mirror with a table of contents.
