interface-design

Use it when
you're building or reviewing a dashboard, admin panel, settings page or other product UI, not a landing page
It does
explores the product's domain, the colors of its world and one signature element, proposes a direction, then builds and checks it
You get
UI code with stated intent, hierarchy, palette, depth, type and spacing, and on request a .interface-design/system.md that later sessions follow
Unlike
general frontend or marketing design skills, it's only for product UI
Shows
palettes, type and components rendered in the chat, when your agent has an inline rendering tool

TLDR

It assumes the agent will produce a generic dashboard and works against that. Before any code it settles who the user is, what they must do and how the product should feel, then writes down the product's domain concepts, the colors of its world, one signature element only this product could have, and three obvious defaults to reject. Before each component it states intent, focal element, palette, depth, surfaces, type and spacing, and why. Its rules cover hierarchy (one focal point, a type scale from a ratio, weight over size), density, quiet surface elevation and low-contrast borders, tokens named for the product, every interaction and data state, and short motion, mostly under 300 ms, that respects reduced motion. It reuses native HTML, the project's components and headless primitives before hand-rolling controls. It edits the code, runs the build and tests, checks the result visually, and runs four checks before showing you: swap, squint, signature and token. Then it offers to save the decisions to .interface-design/system.md, which later sessions read and keep to.
