technology-stack-blueprint-generator

Use it when
you want a written record of what a codebase is built with and how its code is usually written, so new code stays consistent
You get
a Technology_Stack_Blueprint file in Markdown, JSON, YAML or HTML
It does
reads project, config and build files to detect the stacks, then documents dependencies, conventions and representative code from the project
Settings
project type or auto-detect, a depth from Basic to Implementation-Ready, and switches for versions, licenses, diagrams, usage patterns and conventions
Covers in detail
.NET, Java, JavaScript, React and Python

TLDR

A parameterized prompt: variables at the top decide which sections the agent writes. It scans files such as package.json, .csproj and pom.xml, build scripts and pipeline definitions to identify languages, frameworks and dependencies, with exact versions and licenses if you ask for them. For each stack it finds, it documents the specifics, such as NuGet packages and dependency injection for .NET, Spring Boot setup for Java, hooks and state management for React, or the web framework and ORM for Python. Optional sections cover naming and code-organization conventions; example code from the project for endpoints, data access, services and UI components; a technology map of integration points, tooling and infrastructure; diagrams of how the stack fits together; and, at the Implementation-Ready depth, file templates, snippets and a checklist for building new features. It ends with the apparent reasons behind technology choices, legacy parts marked for replacement and upgrade paths.
