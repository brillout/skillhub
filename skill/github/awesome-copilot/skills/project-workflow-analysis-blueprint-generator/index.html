project-workflow-analysis-blueprint-generator

Use it when
you want an agent or a new developer to add features the way the existing code already does them
It does
detects the stack, entry points and persistence, then traces each workflow from its entry point through services, mapping, data access, responses, errors and async work
You get
documentation of each workflow with the files and real code involved, naming conventions, reusable code templates and implementation guidelines
Configure
variables set the project type, entry point, persistence, architecture pattern, number of workflows, detail level, test patterns and a sequence diagram
Unlike
folder-structure-blueprint-generator, from the same repo, which maps where files live; this follows how a request moves through them

TLDR

A prompt template for writing down how a codebase actually implements its features. It starts by detecting the technologies, the entry points (API controllers, GraphQL resolvers, UI components that call APIs, message handlers, scheduled jobs) and the persistence (database contexts, repositories, ORM mappings, API clients, file access). For each workflow it names the business purpose, the trigger and every file or class involved, then documents the entry point with its full signature and request model, the services and their dependency injection, DTO-to-domain mapping, data access with the actual queries, response construction and status codes, error handling down to retries and compensating actions, and background jobs or events. Optional sections add test patterns and a sequence diagram. It then records naming conventions for controllers, services, repositories and DTOs, gives code templates for a new endpoint, service method, repository method and domain model, and ends with guidance: the order to build a similar feature in, pitfalls in the current code and its extension points. Patterns specific to .NET, Spring and React are covered when detected.
