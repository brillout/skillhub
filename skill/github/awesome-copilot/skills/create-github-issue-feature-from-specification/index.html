create-github-issue-feature-from-specification

Use it when
you have a written specification and want it tracked as a single GitHub feature request
It does
pulls the requirements from the spec, searches existing issues, then creates a new issue or updates the matching one
You get
one issue titled with the feature name, holding the problem, proposed solution and context, labelled feature or enhancement
Uses
the repo's feature_request.yml issue template, or the default one when there's none

Calls search_issues, create_issue and update_issue, tools such as the GitHub MCP server provides, so connect one first.

TLDR

A short command for spec-driven work on GitHub. You point it at a specification file; the agent reads it for requirements and checks existing issues with search_issues so it doesn't open a duplicate. It then files one issue for the whole specification with create_issue, or updates the existing one with update_issue, following the repo's feature_request.yml template and falling back to the default. The title names the feature from the specification, the description holds the problem statement, proposed solution and context, the issue includes only changes the specification requires, and it gets feature or enhancement labels as appropriate.

Create GitHub Issue from Specification

Create GitHub Issue for the specification at ${file}.

Process

  1. Analyze specification file to extract requirements
  2. Check existing issues using search_issues
  3. Create new issue using create_issue or update existing with update_issue
  4. Use feature_request.yml template (fallback to default)

Requirements

  • Single issue for the complete specification
  • Clear title identifying the specification
  • Include only changes required by the specification
  • Verify against existing issues before creation

Issue Content

  • Title: Feature name from specification
  • Description: Problem statement, proposed solution, and context
  • Labels: feature, enhancement (as appropriate)
