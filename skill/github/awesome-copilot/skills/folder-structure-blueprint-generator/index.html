folder-structure-blueprint-generator

Use it when
you want a codebase's layout conventions written down, so people and agents put new files where they belong
It does
detects the project type and whether it's a monorepo, uses microservices or has a frontend, then documents directories, file placement, naming, entry points, build output and extension
You get
Project_Folders_Structure_Blueprint.md, with a folder tree drawn as ASCII, nested lists or a table, ending with a note on keeping it current
Detects
.NET, Java, React, Angular, Python, Node.js and Flutter projects from their solution, build and package files
Unlike
project-workflow-analysis-blueprint-generator, from the same repo, which follows how a request moves through the code; this maps where the code lives

TLDR

A prompt template. Configuration variables at the top choose the project type or auto-detection, whether it's a monorepo, uses microservices or has a frontend, how to draw the tree and how many levels deep, and whether to include file counts, generated folders such as node_modules, file placement patterns and templates. Auto-detection looks for .sln and .csproj files, pom.xml or build.gradle, package.json with files such as angular.json or next.config.js, requirements.txt or pyproject.toml, and pubspec.yaml. The blueprint covers the organizing principle (by feature, layer or domain), the directory tree, what each significant directory holds, where configuration, models, business logic, interfaces, tests and docs go, naming conventions for files, folders and namespaces, entry points and where to add features or tests, build and output layout, patterns specific to .NET, Java and Node.js, how the structure scales, optional templates for a new feature, component, service or test, and the tools or checks that enforce the structure.

Project Folder Structure Blueprint Generator

${INCLUDES_MICROSERVICES="Auto-detect|true|false"} <!-- Is this a microservices architecture? -->

${INCLUDES_FRONTEND="Auto-detect|true|false"} <!-- Does project include frontend components? -->

${IS_MONOREPO="Auto-detect|true|false"} <!-- Is this a monorepo with multiple projects? -->
