TLDR

A short command for turning a plan into tracked work. You point it at a plan file, and it splits the plan into its phases, one issue each. Before creating anything it searches the repository's issues with search_issues, so a phase that already has an issue gets that issue updated with update_issue instead of a duplicate; new ones go through create_issue. Each issue takes the phase name as its title and the phase's details, requirements and context as its description, limited to the changes the plan requires, with labels that fit a feature or a chore. It uses the feature_request.yml or chore_request.yml issue template when the repository has one, and the default template otherwise.

Create GitHub Issue from Implementation Plan

Create GitHub Issues for the implementation plan at ${file}.

Process

  1. Analyze plan file to identify phases
  2. Check existing issues using search_issues
  3. Create new issue per phase using create_issue or update existing with update_issue
  4. Use feature_request.yml or chore_request.yml templates (fallback to default)

Requirements

  • One issue per implementation phase
  • Clear, structured titles and descriptions
  • Include only changes required by the plan
  • Verify against existing issues before creation

Issue Content

  • Title: Phase name from implementation plan
  • Description: Phase details, requirements, and context
  • Labels: Appropriate for issue type (feature/chore)
