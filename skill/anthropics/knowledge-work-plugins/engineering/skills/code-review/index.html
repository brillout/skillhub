TLDR

A review command. Point it at a PR URL, a diff or files; with nothing given, it asks what to review. It looks through four lenses. Security covers the OWASP top 10, such as SQL injection, XSS, CSRF, authentication and authorization flaws, secrets in code, insecure deserialization, path traversal and SSRF. Performance covers N+1 queries, needless allocations, quadratic work in hot paths, missing indexes, unbounded queries and resource leaks. Correctness covers empty or null input, overflow, race conditions, error handling, off-by-one errors and type safety. Maintainability covers naming, single responsibility, duplication, test coverage and comments on non-obvious logic. The report has a one- or two-sentence summary, a table of critical issues with file, line and severity, a table of suggestions by category, what looks good, and a verdict. It works on its own; with source control, project tracker or knowledge base connectors it also pulls the diff, checks CI and test results, links findings to tickets, checks that the PR meets its stated requirements, and compares the change with your team's standards. Saying the code is a hot path or handles PII focuses the review.

Review Dimensions

Security
  • SQL injection, XSS, CSRF
  • Authentication and authorization flaws
  • Secrets or credentials in code
  • Insecure deserialization
  • Path traversal
  • SSRF
Performance
  • N+1 queries
  • Unnecessary memory allocations
  • Algorithmic complexity (O(n²) in hot paths)
  • Missing database indexes
  • Unbounded queries or loops
  • Resource leaks
Correctness
  • Edge cases (empty input, null, overflow)
  • Race conditions and concurrency issues
  • Error handling and propagation
  • Off-by-one errors
  • Type safety
Maintainability
  • Naming clarity
  • Single responsibility
  • Duplication
  • Test coverage
  • Documentation for non-obvious logic
