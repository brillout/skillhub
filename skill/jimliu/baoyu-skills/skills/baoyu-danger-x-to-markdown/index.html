baoyu-danger-x-to-markdown

Use it when
you want a tweet, a thread or an X Article saved as a Markdown file

Uses an unofficial, reverse-engineered X API with your login cookies: it may break, and X may restrict your account.

TLDR

It relies on a reverse-engineered X API rather than an official one. Before the first conversion it shows a disclaimer and saves your acceptance in a consent file; declining stops it. Also before its first conversion, it asks about downloading media, the output folder and where to keep these preferences, and never assumes defaults. It takes x.com and twitter.com status links and X Article links, and can print JSON instead of Markdown. Cookies come from the X_AUTH_TOKEN and X_CT0 environment variables or, failing those, from a Chrome window it opens for you to log in, whose cookies it caches locally; --login only refreshes them. When media downloading is left on ask, it saves the Markdown first, checks it for remote images or videos, and only then asks, rerunning with downloads if you say yes.

Media Download

By EXTEND.md download_media: 1 → run with --download-media; 0 → run without; ask (default):

  1. Run without --download-media → markdown saved
  2. Check it for remote media (https:// image/video links); none → done, no prompt
  3. Otherwise ask (header "Media", question "Download N images/videos to local files?"): "Yes" — download to local directories / "No" — keep remote URLs
  4. Yes → rerun with --download-media (overwrites markdown with localized links)

Authentication

  1. Environment variables (preferred): X_AUTH_TOKEN, X_CT0
  2. Chrome login (fallback): auto-opens Chrome, caches cookies locally
